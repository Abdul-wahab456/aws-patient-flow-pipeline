## 1. Project summary

An end-to-end, code-first data pipeline on AWS that ingests **synthetic hospital data in FHIR format** (generated by Synthea), processes it through a **bronze → silver → gold medallion architecture**, and produces **patient-flow KPIs** (length of stay, 30-day readmissions, admissions/discharges, ED volume).

**Goals**
- Hands-on AWS data-engineering experience using **AWS CLI + Python code** (no console clicking for building resources).
- Practice with healthcare data (FHIR JSON), nested JSON flattening in PySpark, incremental loads, Iceberg `MERGE`, star-schema modeling, and orchestration.
- A clean, documented **GitHub portfolio project**.

**Owner:** Jared (data engineer; experienced with Databricks, Delta Lake, Snowflake, Azure; learning AWS Glue).

## 3. Architecture

```
  Synthea (laptop) --> split into 10 packets --> S3 landing/   (one-time upload)

                 EventBridge Scheduler  (alarm clock, daily)
                              |
                              v
                 Step Functions  (manager, runs steps in order)
                              |
     +------------------------+------------------------+
     |                                                 |
     v                                                 v
  [1] Lambda  ---->  [2] Glue job  ---->  [3] Athena MERGE  ---->  [4] DQ checks
  copy packet        clean + flatten      upsert into gold         test gold data
     |                    |                     |
     v                    v                     v
  BRONZE              SILVER                 GOLD                  Notebook
  S3 raw/      -->    S3 silver/     -->     S3 gold/       -->    KPI charts
  FHIR JSON           Parquet                Iceberg tables        (awswrangler)

  Top row    = AWS services doing the work
  Bottom row = where the data is stored (all folders in one S3 bucket)
```

**Daily run (Step Functions):**
1. `pf-ingest` Lambda copies the next landing batch → `raw/fhir/ingest_date=YYYY-MM-DD/`
2. If no batches remain → succeed and stop.
3. Glue job flattens FHIR bundles for that `ingest_date` → silver Parquet tables (catalog updated).
4. Athena runs `MERGE INTO` statements (dims first, then fact) → gold Iceberg tables.
5. Athena runs data-quality check queries; fail the execution if a check fails.

## 4. Data source: Synthea

- Download: `https://github.com/synthetichealth/synthea/releases/download/master-branch-latest/synthea-with-dependencies.jar` (save to `data_generation/`, **gitignored**).
- Generate a **small** population with limited history to control size and cost, e.g.:
  ```powershell
  java -jar synthea-with-dependencies.jar -p 300 -s 42 `
    --exporter.years_of_history 5 `
    --exporter.fhir.export true `
    Massachusetts
  ```
  (Verify flags against the Synthea README; adjust `-p` if output is too large. Target total raw size: **< 500 MB**.)
- Output (`output/fhir/`):
  - One **FHIR transaction Bundle JSON per patient** (Patient, Encounter, Condition, Observation, etc. in `entry[].resource`).
  - `hospitalInformation*.json` → Organization / Location resources.
  - `practitionerInformation*.json` → Practitioner / PractitionerRole resources.
- **References**: Synthea uses both `urn:uuid:<id>` references and conditional references like `Organization?identifier=...|<id>` / `Practitioner?identifier=...|<npi>`. **Inspect real samples first** and write a helper that resolves both formats into plain IDs.

**Simulating a daily feed**
- `data_generation/split_batches.py` splits patient bundle files into **10 batches** → `data/landing/batch_01 … batch_10`.
- `hospitalInformation*` and `practitionerInformation*` go into **batch_01**.
- A batch = a group of patients. The **simulated arrival date** is deterministic: `ingest_date = 2026-11-01 + (batch_number - 1) days`.
- Upload once: `aws s3 sync data/landing s3://<LAKE_BUCKET>/landing/`

## 6. Data model

### 6.1 Silver tables (`pf_silver`, Parquet, partitioned by `ingest_date` string `YYYY-MM-DD`)

| Table | Columns (minimum) |
|---|---|
| `patient` | patient_id, gender, birth_date, deceased_datetime, marital_status, city, state, postal_code, ingest_date |
| `encounter` | encounter_id, patient_id, status, encounter_class (e.g. AMB/EMER/IMP — **check distinct values in data**), type_code, type_display, start_ts, end_ts, organization_id, practitioner_id, reason_code, reason_display, ingest_date |
| `condition` | condition_id, patient_id, encounter_id, code, display, clinical_status, onset_ts, abatement_ts, ingest_date |
| `organization` | organization_id, name, type, city, state, postal_code, ingest_date |
| `practitioner` | practitioner_id, npi, full_name, gender, ingest_date |

Rules: timestamps cast to `timestamp`, IDs as plain strings (no `urn:uuid:` prefix), deduplicate within the batch.

### 6.2 Gold tables (`pf_gold`, **Apache Iceberg**, created via Athena DDL)

| Table | Grain / key | Notes |
|---|---|---|
| `dim_patient` | patient_id | SCD Type 1 via `MERGE`; include `age_years` (as of `current_date`), `age_group` |
| `dim_facility` | organization_id | from organization |
| `dim_practitioner` | practitioner_id | from practitioner |
| `dim_date` | date | one-time CTAS using `sequence()` + `UNNEST` (2015-01-01 → 2027-12-31): year, quarter, month, day_of_week, is_weekend |
| `fact_encounter` | encounter_id | patient_id, organization_id, practitioner_id, encounter_class, start_ts, end_ts, start_date, end_date, los_hours, los_days, is_inpatient, is_emergency, reason_code, reason_display, primary_condition_code; partitioned by `month(start_ts)` |

**MERGE rules**
- Source = silver rows for the current `ingest_date` only.
- Deduplicate the source with `ROW_NUMBER()` so each target key matches at most one row.
- `WHEN MATCHED THEN UPDATE`, `WHEN NOT MATCHED THEN INSERT`.
- Re-running the same `ingest_date` must **not** create duplicates (idempotent).
- Pass `ingest_date` from Step Functions using Athena `ExecutionParameters` or `States.Format`.

### 6.3 KPI views (`pf_gold`, Athena views)

| View | Definition |
|---|---|
| `vw_daily_admissions_discharges` | inpatient admissions by `start_date`, discharges by `end_date` |
| `vw_avg_los_by_facility_month` | avg/median `los_days` for inpatient encounters by facility & month |
| `vw_readmission_30d` | inpatient encounter is a readmission if it starts within 30 days after the same patient's previous inpatient discharge (`LAG` over patient ordered by start_ts); rate by month and facility |
| `vw_ed_volume_by_hour_dow` | emergency encounters by hour of day × day of week |
| `vw_top_reasons` | top encounter reasons / conditions by volume |

  - `pf-lambda-role`: trust lambda; S3 read `landing/`, `state/`; write `raw/`, `state/`; CloudWatch Logs (`AWSLambdaBasicExecutionRole`).

  - `pf-sfn-role`: trust states; invoke `pf-ingest`; Glue `StartJobRun/GetJobRun/GetJobRuns/BatchStopJobRun`; Athena `StartQueryExecution/GetQueryExecution/GetQueryResults/StopQueryExecution`; Glue Catalog read/write (`GetDatabase`, `GetTable`, `GetPartitions`, `CreateTable`, `UpdateTable`, `BatchCreatePartition`, ...); S3 on lake bucket + results bucket; CloudWatch Logs delivery.

  - Least privilege: scope resources to the project bucket/ARNs.
- **Done when:** `aws s3 ls`, `aws glue get-databases`, `aws athena get-work-group --work-group pf-wg`, `aws iam get-role` all confirm resources.

### Phase 4 — Ingestion Lambda (bronze)
- `lambda/ingest/handler.py`:
  - Read `state/ingest_state.json` (`{"next_batch": 1}`; create if missing).
  - Optional event override: `{"batch": N}` for reruns.
  - If batch > 10 → return `{"status": "NO_MORE_BATCHES"}`.
  - Compute `ingest_date = 2026-11-01 + (batch-1) days`.
  - Copy every object from `landing/batch_NN/` → `raw/fhir/ingest_date=<date>/` (server-side `copy_object`).
  - Write manifest `raw/fhir/ingest_date=<date>/_manifest.json` (batch, file count, bytes, timestamp).
  - Update state only after successful copy. Structured logging.
  - Return `{"status": "OK", "batch": N, "ingest_date": "...", "file_count": n}`.
- `04_deploy_lambda.ps1`: zip + `aws lambda create-function` / `update-function-code`.
- Test: `aws lambda invoke --function-name pf-ingest --payload ...` then `aws s3 ls` the raw partition.
- **Done when:** batch 1 lands in raw; rerun with override doesn't break state.

### Phase 5 — Glue job (bronze → silver)
- Develop logic in `glue_jobs/fhir_utils.py` (pure functions, unit tests in `tests/`).
- Dev option A (free): official AWS Glue Docker image locally against sample files. Dev option B: Glue interactive session with idle timeout ≤ 15 min (costs per minute — stop when done).
- `bronze_to_silver.py` (job argument `--ingest_date`):
  - Read `raw/fhir/ingest_date=<date>/*.json` with `multiLine=true` (skip `_manifest.json`).
  - `explode(entry)` → filter by `resource.resourceType` → select needed fields → resolve references → cast types → dedupe.
  - Use explicit schemas if inference is slow or inconsistent.
  - **Idempotent write:** purge the target partition path first (`glueContext.purge_s3_path`), then write Parquet partitioned by `ingest_date` and **register/update tables + partitions in `pf_silver`** (e.g. `getSink(..., enableUpdateCatalog=True, partitionKeys=["ingest_date"])`). Alternative: Spark dynamic partition overwrite + Athena `ALTER TABLE ADD IF NOT EXISTS PARTITION`.
  - Log row counts per table.
- `05_deploy_glue_job.ps1`: upload scripts to `s3://<LAKE_BUCKET>/scripts/`, `aws glue create-job` / `update-job` (G.1X, 2 workers, timeout 10, retries 0, `--extra-py-files` for `fhir_utils.py`).
- Test: `aws glue start-job-run --job-name pf-bronze-to-silver --arguments '--ingest_date=2026-11-01'`, poll `get-job-run`, then query silver tables in Athena.
- Optional learning task: Glue Crawler over `raw/` into `pf_bronze` to see how crawlers infer nested FHIR schemas (not part of the daily pipeline).
- **Done when:** all 5 silver tables queryable in Athena for batch 1; rerun gives the same row counts.

### Phase 6 — Gold layer (Athena + Iceberg)
- `sql/gold/ddl/`: `CREATE TABLE ... LOCATION 's3://<LAKE_BUCKET>/gold/<table>/' TBLPROPERTIES ('table_type'='ICEBERG')` for all gold tables; `dim_date` via CTAS.
- `sql/gold/merge/`: one `MERGE INTO` per table (Section 6.2 rules). Order: dims → fact.
- `sql/gold/views/`: KPI views (Section 6.3).
- Small Python helper (`infra/run_athena_sql.py`, boto3) to run a SQL file against `pf-wg` and wait for completion — used for DDL and manual testing.
- **Done when:** gold tables populated for batch 1; re-running the merges produces no duplicates; all views return sensible results.

### Phase 7 — Orchestration
- `step_functions/pf_daily_pipeline.asl.json` (template; `06_deploy_state_machine.ps1` fills in ARNs, bucket, workgroup and embeds SQL):
  1. `Ingest` — Lambda invoke (`arn:aws:states:::lambda:invoke`)
  2. `HasNewBatch?` — Choice: `NO_MORE_BATCHES` → `Succeed`
  3. `BronzeToSilver` — `arn:aws:states:::glue:startJobRun.sync` with `--ingest_date`
  4. `MergeDims` — sequential Athena tasks `arn:aws:states:::athena:startQueryExecution.sync`
  5. `MergeFact` — Athena task
  6. `DataQuality` — Athena DQ queries; Choice → `Fail` if any check fails
  7. Retry (with backoff) on transient errors; `Catch` → `Fail` state with error info
- Enable CloudWatch logging for the state machine (level ERROR).
- `07_create_schedule.ps1`: EventBridge Scheduler daily cron (Asia/Karachi), **state DISABLED**.
- Test: `aws stepfunctions start-execution` manually for batches 2–3; check `describe-execution`.
- **Done when:** one execution runs the full flow end to end; a rerun is idempotent; the run with no batches left exits cleanly.

### Phase 8 — Data quality & notebooks
- `sql/dq/` checks (each returns a failure count; 0 = pass):
  - null/duplicate primary keys in silver and gold
  - `end_ts < start_ts`
  - encounters whose `patient_id` is missing from `dim_patient` (referential integrity)
  - silver row count for the batch > 0
- Optionally write DQ results to `s3://<LAKE_BUCKET>/dq/` as a small results table.
- `02_data_quality.ipynb`: run DQ queries with `awswrangler` (`wr.athena.read_sql_query(..., workgroup="pf-wg", ctas_approach=False)`), show trends per batch.
- `03_kpi_analysis.ipynb`: charts for each KPI view.
- **Done when:** notebooks run top to bottom without errors.

## 9. Cost guardrails (must follow)

- Glue job: **2 × G.1X workers, 10-minute timeout, 0 retries.** Rough cost: a few cents per run (Glue bills per DPU-hour with a 1-minute minimum; check current `us-east-1` pricing).
- Never leave Glue interactive sessions running; set idle timeout.
- Athena: workgroup 1 GB scan cutoff; query partitioned/Iceberg tables with filters; results bucket expires after 7 days.
- EventBridge schedule stays **DISABLED** unless explicitly enabled.
- Keep raw data < 500 MB.
- Lambda, Step Functions and Glue Catalog usage stays within always-free / tiny amounts.
- Check spend regularly: `aws freetier get-account-plan-state` and the Billing console.
- **Expected total: well under $10.**

## 10. Security rules (must follow)

- Never use or create root access keys. Never print, log or commit credentials.
- `config/settings.json`, `.env`, data files and Synthea output are gitignored.
- S3 buckets: Block Public Access ON, default encryption ON.
- IAM roles scoped to project resources (least privilege).
- Data is synthetic only — no real patient data, ever.
